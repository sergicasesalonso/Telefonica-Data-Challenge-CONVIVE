# 3.3.2 User guide: run the notebook and read the dashboard

CONVIVE · Team 102_A · final delivery (RQ-13, RQ-14). For the two people who will use the product: the **reader**, who opens the dashboard, and the **analyst**, who runs it again with new data.

## 1. What you need

| | Reader | Analyst |
|---|---|---|
| Computer | Any laptop with Windows, macOS or Linux | The same, 16 GB of memory recommended |
| Software | Python 3.11 or later | Python 3.11 or later |
| Disk | 1 GB | 1 GB, plus 16 GB of raw files and 1.5 GB of Parquet |
| Data | The aggregated tables (`deliverables/`, received from the team) | The Smart Steps monthly files, under the NDA |
| Internet | Only to install | Only to install |

## 2. Open the dashboard (reader, 5 minutes)

1. Unzip the package and open a terminal in its folder.
2. Install, once: `python -m pip install -r requirements.txt`
3. Start: double click on `start_dashboard.bat` (Windows), or run `python -m streamlit run app/dashboard.py`
4. The browser opens `http://localhost:8501`. To stop, close the terminal.

The dashboard works without internet and is reachable only from this computer. Do not deploy it online: the tables come from data under NDA.

## 3. Read the dashboard

**Filters (left).** Year, month range, visitor origin, visitor type, days, district and neighbourhood. They apply to every view; under each title the dashboard says when one of them cannot apply. The line under the main title repeats the active selection.

| Tab | The question it answers | Example |
|---|---|---|
| Key findings | What did we learn? | The Charter question, its rule and its verdict |
| Visitors & residents | Who moves in each neighbourhood, and when? | Choose District = Ciutat Vella and Days = Weekends |
| Q1-Q6 views | Where, when and how many, by origin | Choose Year = 2024 and Type = Overnight tourist |
| Overnight stays | How many nights do tourists spend? | Compare national and international |
| Research answers | Is this belief true? | Select Q4 and read rule, answer and verdict |
| Neighbourhood explorer | What happens in this neighbourhood? | el Barri Gòtic, then Verdun |
| Who visits | Where do visitors live? | Switch to Province |
| Nationalities | What is special about this country? | South Korea and el Carmel |
| Data quality | Can I trust this number? | Low-data neighbourhoods and level shifts |

**Six rules to read a number.**

1. *Unique visitors* are people in a place and a period. They cannot be added across days, months or neighbourhoods, so a long period is shown as a monthly mean.
2. *Presences* are sums of visitors across neighbourhoods. A person seen in two neighbourhoods counts twice. The dashboard uses this word when you select an area.
3. *Trips* are journeys between neighbourhoods. One person can make several. Trips and visitors are never combined.
4. `<15`, 0 and NA never mean "nobody". Counts below 15 are hidden for privacy.
5. A verdict (Yes, Partly, No) comes from a rule fixed before computing. Green, orange or red tells if it survives a small change of that rule.
6. The results describe patterns, not causes.

## 4. Run the analysis again (analyst)

1. Put the monthly files in `data/output_limite_legal_mobilidad/YYYY-MM/` and `data/output_limite_legal_turismo/YYYYMM/`, and the neighbourhood GeoJSON in `data/geo/`.
2. Run `python run_final.py`. It converts, checks, cleans, aggregates, validates, answers, draws and tests. It stops at the first step that fails.
3. To build the executed notebook as well: `python run_final.py --notebook`. To read it without running it, open `CONVIVE_Final.ipynb`.
4. Without the raw files, `python run_final.py --from-tables` rebuilds everything after the aggregated tables.

| Step | Output to check |
|---|---|
| Quality | `deliverables/iteration2/3.1.2_data_quality_report.md` |
| Validation | `deliverables/iteration3/2.2.2_validation_log.md` (0 failed) |
| Answers | `deliverables/iteration3/3.2.4_quantified_answers.md` |
| Findings and limits | `deliverables/final/5.2_key_findings.md`, `5.3_limitations.md` |
| Dashboard | `app/check_dashboard.py` prints ALL CHECKS PASSED |

## 5. If something fails

| You see | Do this |
|---|---|
| `No module named ...` | Run the install command again with the same Python you use to start |
| "Run `python run_final.py`..." inside a tab | The aggregated tables are missing: copy `deliverables/` from the package, or run `python run_final.py` |
| `Port 8501 is already in use` | Add `--server.port 8502` to the start command |
| Validation failed | Open `2.2.2_validation_log.md`: the failed check names the table. Do not use the results until it passes |
| A map is empty | `data/geo/barris_bcn.geojson` is missing |

## 6. Confidentiality

Raw files never leave `data/` (git-ignored). Share aggregated tables only with people covered by the NDA. Screenshots show aggregated values, and any value below 15 reads `<15`.
